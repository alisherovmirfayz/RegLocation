# RegLocation

Облачная система учёта присутствия учителей и **расчётного** местоположения в школе в реальном времени.
Местоположение определяется по расписанию и назначениям директора — **без GPS**. На всех экранах это явно указано.

| Интерфейс | Адрес | Для кого |
|---|---|---|
| Монитор ресепшена | `https://monitor.example.com/monitor` | Большой экран в холле |
| Сайт учителя | `https://app.example.com/teacher` | Телефоны учителей (Android, iPhone) |
| Кабинет директора | `https://app.example.com/director` | Компьютер или планшет |

Часовой пояс: **Asia/Tashkent**. Все интерфейсы на русском языке.

## 1. Структура репозитория

```
RegLocation/
├── monitor-backend/        Проект №1 — backend (API, Socket.IO, OCR, БД) + монитор ресепшена
│   ├── src/                сервер: Express, Socket.IO, Prisma, логика местоположений, OCR
│   ├── monitor/            React-приложение монитора (/monitor, /monitor/login)
│   ├── prisma/             схема PostgreSQL и миграции
│   ├── tests/              автотесты (API, Socket.IO, OCR, граничные моменты времени)
│   ├── Dockerfile, railway.json, .env.example
├── teacher-director/       Проект №2 — сайт учителя и кабинет директора
│   ├── src/teacher/        /teacher — вход, кабинет, расписание, профиль
│   ├── src/director/       /director, /director/login, /director/register и все разделы
│   ├── server/server.mjs   веб-сервер: раздаёт сайт и проксирует /api и /socket.io на backend
│   ├── Dockerfile, railway.json, .env.example
├── render.yaml             автоматическое развёртывание на Render (Blueprint)
├── .github/workflows/      CI (тесты, сборка, Docker) и ежедневная резервная копия БД
└── docs/plans/             исходные чертежи этажей
```

Проекты независимы: у каждого свои `package.json`, сборка, Dockerfile и деплой. Общая база данных находится в backend проекта №1, проект №2 обращается к ней только через API.

## 2. Как это работает

- **Учитель** входит с телефона, нажимает «Я в школе». Сервер вычисляет, где он сейчас должен быть, и сразу отправляет изменения на монитор через Socket.IO.
- **Приоритет определения места:** не в школе → не показывается; обед (12:30–13:15) и полдник (15:45–16:05) → столовая; ручное назначение директора; директор → кабинет директора; завуч → кабинет завуча; идёт урок → кабинет из расписания; иначе → учительская.
- **В 17:00** все отметки автоматически закрываются, повторная отметка возможна только на следующий день. Логика устойчива к перезапуску сервера: проверка выполняется по базе данных, а не «будильником».
- **Расписание** учитель загружает фото или PDF: система находит таблицу, дни недели, белые ячейки классов и оранжевые ячейки кабинетов, сверяет кабинеты с базой помещений, подсвечивает сомнительные ячейки — учитель проверяет и подтверждает.
- **Тестовый режим** директора показывает на мониторе любой день и время, не меняя реальных отметок.

## 3. Публикация на GitHub

GitHub хранит исходный код. Сам сайт работает на облачном сервере (Railway или Render), который автоматически берёт код из GitHub.

**Вариант без командной строки (GitHub Desktop):**
1. Зарегистрируйтесь на <https://github.com>, установите <https://desktop.github.com>.
2. GitHub Desktop → *File → Add local repository* → выберите папку `RegLocation` → *Create a repository*.
3. Убедитесь, что в списке изменений **нет** файлов `.env`, папок `node_modules` и `dist` (они исключены через `.gitignore`).
4. *Commit to main* → *Publish repository* → отметьте **Keep this code private** → *Publish*.

**Вариант через git:**
```bash
cd RegLocation
git init -b main
git add .
git commit -m "RegLocation"
git remote add origin https://github.com/<ваш-аккаунт>/reglocation.git
git push -u origin main
```

> Никогда не добавляйте в репозиторий пароли, SMTP-ключи и строки подключения к базе — они задаются только в панели хостинга.

## 4. Размещение на Railway (рекомендуется)

Railway поддерживает постоянно работающий Node.js, WebSocket, PostgreSQL с постоянным диском, HTTPS и автодеплой из GitHub. Нужен платный план (Hobby, от ~5 $/мес), чтобы сервисы не останавливались.

1. <https://railway.com> → войдите через GitHub → **New Project → Deploy from GitHub repo** → выберите репозиторий.
2. **База данных:** в проекте нажмите **+ New → Database → PostgreSQL**.
3. **Сервис №1 (backend + монитор).** Откройте созданный сервис → *Settings*:
   - *Root Directory*: `/monitor-backend`
   - *Config as code → Railway config file*: `/monitor-backend/railway.json`
   - *Service name*: `reglocation-monitor`
   - *Networking → Generate Domain* (получите адрес вида `reglocation-monitor-production.up.railway.app`).
   - *Variables* — добавьте:

     | Переменная | Значение |
     |---|---|
     | `DATABASE_URL` | `${{Postgres.DATABASE_URL}}` |
     | `NODE_ENV` | `production` |
     | `PORT` | `8080` |
     | `PUBLIC_MONITOR_URL` | `https://<домен сервиса №1>` |
     | `PUBLIC_APP_URL` | `https://<домен сервиса №2>` (заполните после шага 4) |
     | `INITIAL_DIRECTOR_EMAIL` | email директора-владельца |
     | `MAIL_TRANSPORT`, `SMTP_*`, `MAIL_FROM` | см. раздел 6 |
     | `TRUST_PROXY` | `1` |
4. **Сервис №2 (учитель + директор):** *+ New → GitHub Repo* → тот же репозиторий:
   - *Root Directory*: `/teacher-director`, *Railway config file*: `/teacher-director/railway.json`
   - *Service name*: `reglocation-app`, *Generate Domain*
   - *Variables*: `API_UPSTREAM` = `http://${{reglocation-monitor.RAILWAY_PRIVATE_DOMAIN}}:8080`, `PORT` = `8080`, `NODE_ENV` = `production`
5. Вернитесь в сервис №1 и укажите `PUBLIC_APP_URL` = адрес сервиса №2.
6. Проверка: откройте `https://<сервис №1>/api/health` — должно быть `{"status":"ok","db":"ok"}`.
7. **Свои домены** (необязательно): *Settings → Networking → Custom Domain* → `monitor.ваша-школа.uz` для сервиса №1 и `app.ваша-школа.uz` для №2, добавьте CNAME-записи у регистратора. HTTPS-сертификаты выпускаются автоматически. После этого обновите `PUBLIC_MONITOR_URL` и `PUBLIC_APP_URL`.
8. *Settings → Deploy*: включите **Wait for CI** — тогда обновление выкатывается только после успешных тестов GitHub Actions.

**Миграции** применяются автоматически при каждом запуске (`prisma migrate deploy`): добавляются новые таблицы и столбцы, существующие данные не удаляются. CI дополнительно блокирует миграции с `DROP`/`TRUNCATE`/`DELETE`.

**Файлы** (фото, исходники расписаний, логотип) по умолчанию хранятся в PostgreSQL — они не теряются при перезапуске и деплое. Временный диск контейнера не используется. Для больших объёмов можно переключиться на S3-совместимое хранилище (`STORAGE_DRIVER=s3`, Cloudflare R2 / Backblaze B2 / AWS S3).

## 5. Альтернатива: Render

1. <https://render.com> → *New → Blueprint* → выберите репозиторий. Render прочитает `render.yaml` и создаст базу `reglocation-db`, сервисы `reglocation-monitor` и `reglocation-app`.
2. Заполните переменные, помеченные «sync: false»: `INITIAL_DIRECTOR_EMAIL`, `SMTP_HOST`, `SMTP_USER`, `SMTP_PASS`, `MAIL_FROM`.
3. Если Render выдал другие адреса, исправьте `PUBLIC_MONITOR_URL` и `PUBLIC_APP_URL` у `reglocation-monitor`.
4. В настройках каждого сервиса можно выбрать *Auto-Deploy: After CI Checks Pass*.

Используются платные планы (`starter` и `basic-256mb`): бесплатные сервисы засыпают, а бесплатная база удаляется через 30 дней.

### 5а. Бесплатно: Vercel + Neon

Оба проекта работают на одном домене Vercel: `/monitor`, `/teacher`, `/director`, а backend — функция Vercel (`api/index.mjs`). Настройки — в `vercel.json`, сборка — `scripts/vercel-build.mjs`.

1. <https://vercel.com> → войдите через GitHub (тариф Hobby, бесплатно, без карты) → *Add New → Project* → репозиторий `RegLocation`. Настройки сборки менять не нужно: они берутся из `vercel.json`.
2. В проекте: *Storage → Create Database → Neon* (бесплатно) → подключить к проекту. Переменные базы появятся автоматически.
3. *Settings → Environment Variables*: `INITIAL_DIRECTOR_EMAIL`, `MAIL_TRANSPORT=smtp`, `SMTP_HOST`, `SMTP_PORT`, `SMTP_SECURE`, `SMTP_USER`, `SMTP_PASS`, `MAIL_FROM` (раздел 6), `CRON_SECRET` (любая длинная случайная строка).
4. *Deployments → Redeploy*. Готово: `https://<проект>.vercel.app/director/register`.

Чем Vercel отличается от Railway/Render (так устроен бесплатный serverless-хостинг):

- **Обновления опросом, а не через Socket.IO.** Страницы запрашивают изменения каждые 5 секунд в учебное время и раз в 30 минут ночью и в выходные (чтобы бесплатная база Neon «засыпала» и не исчерпала лимит). Задержка на мониторе — до 5 секунд.
- **Автоуход в 17:00** выполняется при первом запросе после 17:00 и страховочно — ежедневной задачей Vercel Cron (на бесплатном тарифе раз в сутки, 17:30–18:29).
- **Файлы до 4 МБ.** Большие фото браузер сам уменьшает перед загрузкой; PDF больше 4 МБ нужно уменьшить.
- Тариф Hobby предназначен для некоммерческого использования.

## 6. Почта для кодов подтверждения

Почта нужна для первой регистрации директора и восстановления пароля. Пример с Gmail:

1. Создайте отдельный Gmail для школы, включите двухэтапную аутентификацию.
2. <https://myaccount.google.com/apppasswords> → создайте «пароль приложения».
3. Переменные сервиса №1:
   ```
   MAIL_TRANSPORT=smtp
   SMTP_HOST=smtp.gmail.com
   SMTP_PORT=465
   SMTP_SECURE=true
   SMTP_USER=школа@gmail.com
   SMTP_PASS=<пароль приложения>
   MAIL_FROM=RegLocation <школа@gmail.com>
   ```
Подойдёт любой SMTP-сервис (Brevo, Mailgun, Resend, Яндекс 360).

## 7. Первая регистрация директора

1. Убедитесь, что в переменных сервиса №1 указан `INITIAL_DIRECTOR_EMAIL` и настроена почта.
2. Откройте `https://<app-домен>/director/register` (адрес `/director` при первом запуске сам перенаправит туда).
3. Заполните имя, фамилию, логин, email (тот же, что в `INITIAL_DIRECTOR_EMAIL`), пароль и подтверждение → **«Зарегистрироваться»**.
4. Введите 6-значный код из письма → вы в кабинете директора.

Защита: зарегистрироваться может только владелец указанного email. Ответ сервера одинаков для любого email, поэтому адрес владельца нельзя угадать. Регистрация выполняется атомарной транзакцией — даже при одновременных попытках создаётся ровно один основной аккаунт. После этого страница регистрации навсегда заменяется формой **«Вход директора»**.

**Если директор забыл пароль:** на странице входа «Забыли пароль?» → email → код из письма → новый пароль. Все прежние сеансы завершаются.

## 8. Добавление учителей

1. Кабинет директора → **«Добавить учителя»**.
2. Имя, фамилия, предмет или должность, классы (через запятую: `1B, 6B, 10A`).
   Должность «Директор» или «Завуч» автоматически закрепляет сотрудника за соответствующим кабинетом.
3. **«Создать аккаунт»** → система генерирует уникальный логин (например, `ivanov.a`) и надёжный пароль.
4. Кнопкой «Копировать» передайте данные учителю. **Пароль показывается один раз**; позже его можно только сбросить в разделе «Учителя».

В разделе «Учителя» доступны: редактирование, блокировка, сброс пароля, архив, удаление, фото, история посещаемости.

## 9. Логины для монитора

1. Кабинет директора → **«Доступ к монитору»** → «Создать доступ» → название (например, «Ресепшен 1 этаж») → логин и пароль.
2. На компьютере ресепшена откройте `https://<monitor-домен>/monitor/login`, введите данные, нажмите F11 для полноэкранного режима.
3. Сеанс монитора действует 90 дней — входить каждый день не нужно. Директор может сбросить пароль, заблокировать доступ или завершить все сеансы.

Аккаунт монитора не может создавать учителей или менять школу — у него есть только доступ на просмотр.

## 10. Использование на телефонах

- Учитель открывает `https://<app-домен>/teacher` и входит с выданными логином и паролем.
- **iPhone (Safari):** «Поделиться» → «На экран „Домой“». **Android (Chrome):** меню ⋮ → «Добавить на главный экран». Появится иконка RegLocation как у приложения.
- Утром — **«Я в школе»**, при уходе — **«Выйти из школы»** (одновременно видна только одна кнопка). В 17:00 отметка снимается автоматически.
- **«Расписание»** → «Выбрать файл» → фото или PDF расписания → проверьте ячейки, отмеченные жёлтым → «Подтвердить и сохранить». Лучше всего распознаётся исходный PDF; для фото держите телефон ровно, чтобы таблица была целиком в кадре и резкой.
- Нажатие на аватарку → профиль: смена фото. Пароль учитель изменить не может — его выдаёт и сбрасывает только директор («Учителя» → «Сбросить пароль»).

## 11. Обновления, откат, резервные копии

- **Обновление:** любой `push` в ветку `main` → GitHub Actions запускает тесты → хостинг собирает новую версию и переключает трафик только после успешного health-check (`/api/health`, `/healthz`). Если новая версия не стартует, продолжает работать старая.
- **Откат:** Railway — *Deployments* → предыдущий деплой → **Rollback**. Render — *Events* → **Rollback** к нужной версии.
- **Автоматический перезапуск** при сбое включён (`restartPolicyType: ON_FAILURE`, health-check в Dockerfile).
- **Логи:** вкладка *Logs* сервиса (структурированный JSON).
- **Резервные копии:**
  1. Встроенные копии хостинга (Render — ежедневно на платных планах; Railway — *Backups* в настройках базы).
  2. Ежедневная копия через GitHub Actions (`.github/workflows/backup.yml`): добавьте в *Settings → Secrets → Actions* секрет `BACKUP_DATABASE_URL` (внешняя строка подключения к базе) и, по желанию, `BACKUP_PASSPHRASE` для шифрования. Копии хранятся 30 дней в *Actions → Artifacts*.
  3. Восстановление: `pg_restore --clean --no-owner -d "<DATABASE_URL>" reglocation-YYYY-MM-DD.dump` (для зашифрованной копии сначала `gpg -d файл.gpg > файл.dump`).

## 12. Локальный запуск для разработки

Нужны Node.js 22+ и PostgreSQL 16.

```bash
# Проект №1
cd monitor-backend
cp .env.example .env            # укажите DATABASE_URL, MAIL_TRANSPORT=console, NODE_ENV=development
npm install
npx prisma migrate deploy
npm run dev                     # API: http://localhost:8080, монитор (Vite): http://localhost:5173/monitor

# Проект №2 (в другом окне)
cd teacher-director
npm install
npm run dev                     # http://localhost:5174/teacher и /director
```
В режиме `MAIL_TRANSPORT=console` коды подтверждения печатаются в консоль сервера.

## 14. Безопасность

- Пароли — только хеши **Argon2id** (параметры OWASP); пароли в открытом виде нигде не хранятся.
- Серверные сессии в PostgreSQL; в cookie — случайный токен (`HttpOnly`, `Secure`, `SameSite=Lax`, префикс `__Host-`), в базе — только его SHA-256.
- CSRF: токен сессии в заголовке `X-CSRF-Token` + проверка `Origin`. CORS — только для доменов RegLocation.
- Ограничение попыток входа: по IP и блокировка аккаунта на 15 минут после 5 ошибок.
- Socket.IO принимает только подключения с действующей сессией; учитель получает лишь свои данные.
- Загружаемые файлы проверяются по сигнатуре, а не по расширению. Расписание: PDF, PNG, JPG, HEIC/HEIF (iPhone), WEBP, TIFF (в т.ч. многостраничный), BMP, GIF, AVIF. Размер ограничен (15 МБ, до 6 страниц PDF/TIFF); фото перекодируются (удаляются EXIF/GPS).
- Журнал всех административных действий («История изменений») — кто, когда, что и куда.
- Основной аккаунт директора защищён: создаётся только владельцем email и только один раз.

## 15. Ограничения и честные оговорки

- **Распознавание расписаний не может быть стопроцентным.** На образце школы (скриншот шириной 590 px) система правильно нашла все 31 урок на своих местах, верно прочитала 24 класса из 31, а остальные пометила «Проверьте» — ни одна ошибка не проходит незаметно. PDF с текстовым слоем и качественные изображения распознаются полностью (покрыто тестами). Кабинет никогда не подставляется «по умолчанию»: если номер не прочитан или его нет в базе помещений, ячейка остаётся для ручной проверки.
- Местоположение — **расчётное** (по расписанию и назначениям), а не фактическое.
- Логотип и схемы этажей взяты из присланных изображений (`docs/plans`); директор может уточнить планировку в «Редакторе школы», а логотип заменить в «Настройках».
